### Why this repo exists

Physical infrastructure — pipelines, transmission lines, and their
component assets — had no home in this platform family:
`mwanachama-backend-assetmanager` tracks generic current-state assets, not
a historical record of what a physical asset measured over time. Arrived
at through a dev-research session on 2026-09-03 (recorded as
[DSN-1701](../../../developer/documentation/2.%20design/todo.md)), which
established six things in order: (1) this is a standalone tool, no tie to
Mwanachama's tier/member model; (2) it's a digital twin (historical
telemetry), not a static registry; (3) telemetry readings need a dedicated
table, kept out of `mwanachama-backend-shared`'s shared entity-graph store
to avoid making it the platform's hottest table; (4) six v1 asset types;
(5) assets connect as a directed graph; (6) the reading/metric vocabulary
is expert-configured, not hardcoded.

**Decision: new repo, same architecture as `taskmanager`/`accounting` —
with one fork.** A Go package on `mwanachama-backend-shared`'s Postgres
entity-graph store for the **registry**, imported directly by
`mwanachama-backend-api-gateway`, no gRPC, no sub-service shape — except
telemetry, which gets its own dedicated, service-owned table instead of
riding the shared store. See
[2. design/README.md](../2.%20design/README.md) for the full reasoning.
