| W13 | 🐞 **BUG — a broad/catch-all `RetentionPolicy` purges readings a more specific policy exists to protect, contradicting this package's own documented contract.** `RetentionPolicy.AssetType`'s own doc comment (`telemetry.go`) says an empty `AssetType` "applies to every asset type not covered by a more specific policy" — but `Sweep`/`PurgeBefore` (`retention.go`, `memory_telemetry.go`) implement no precedence at all: each registered policy is applied to the whole reading set independently, with `PurgeBefore(assetType="", ...)` matching *every* asset type and `PurgeBefore(metricName="", ...)` matching *every* metric, regardless of whether a more specific policy also names that (AssetType, MetricName) pair. Demonstrated live: register a specific policy (`AssetType: pipeline, MetricName: pressure_psi, RetentionDays: 365`) meant to keep a year of pressure readings, and a catch-all policy (`AssetType: "", MetricName: "", RetentionDays: 10`) meant to apply only to what the specific policy doesn't cover; record one `pipeline`/`pressure_psi` reading 40 days old (well within the 365-day retention, past the catch-all's 10 days); run `Sweep` — it reports `purged: 1`, and a follow-up `Query` for that asset returns zero readings. The reading the specific policy exists to protect for 365 days is gone after 40. The identical shape recurs one level up: an asset-type-wide policy (`AssetType: pipeline, MetricName: ""`) equally overrides a fully-specific policy scoped to one metric of that same type — same root cause (no most-specific-wins logic anywhere in `Sweep`), not a second bug. Defect location: `retention.go`'s `Sweep` (or `PurgeBefore`'s callers) need to exclude, from a broader policy's purge, any reading that a more specific *registered* policy already covers — the "not covered by a more specific policy" clause `telemetry.go`'s doc comment promises but nothing implements. Pinned by `retention_test.go`'s `TestW13_BroadRulePurgesWhatASpecificRuleShouldHaveProtected` — must go RED once the fix lands. **Carried across the 2026-09-30 conversion unfixed and on purpose**: `Sweep` still applies each rule independently via `PurgeObservationsBefore`, and the names are now `Retention.NodeKind`/`MetricName` over `retention.go`/`observation.go`. `models.Retention.Covers` exists and is deliberately *not* used for precedence — implementing most-specific-wins is the fix, not part of the refactor. | 📋 | — |
| W14 | 📋 **Nothing refuses an unknown `node.kind` any more.** Before the 2026-09-30 conversion, `IsAssetType` refused an asset type outside the closed set of six at write time. The set was six *stored enum values*, every one a utility word, so it had to leave the module — `node.kind` is now a declared `string` the domain fills and the module never interprets. What survives is `required` (a node must be classified) and `matches: "name"` (the strict lowercase-underscore alphabet), so `kind: "pipelin"` is accepted where `kind: "Pipeline!"` is refused. **This is a gap in the standard, not in this repo**: `spec`'s `Blueprint.extend` lets a domain set a **default and nothing else**, so "the module declares the field, each domain declares its values" is not expressible today. Either the engine grows a way for a domain to supply a value set on a roled field — the natural shape, and it would serve every converted module, not just this one — or this module accepts an open vocabulary and says so. Decide before a second domain is provisioned; recorded in [documentation/2. design/declared-domain.md](../2.%20design/declared-domain.md). | 📋 | — |
