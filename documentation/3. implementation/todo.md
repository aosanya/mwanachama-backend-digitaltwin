| W12 | 🐞 **BUG — a caller pushing telemetry for an unregistered/mismatched metric through `ValidatingTelemetryRepository` gets back an opaque `500 {"error":"internal error"}` instead of a `400` naming the problem.** | 📋 | Driven through the real route aggregator (`routes.Routes`) behind `httptest.NewServer` + real `http.Client`: `POST /telemetry/readings` with a `metric_name` that has no registered `MetricDefinition` returns `500 {"error":"internal error"}`; so does a registered metric with a mismatched `unit`, a registered metric posted against the wrong `asset_type`, and one bad reading inside an otherwise-valid `POST /telemetry/readings/batch` call. The *validation logic itself* (`telemetry_validating.go`'s `matchesDefinition`) is correct in every case checked — it correctly rejects an unregistered name, a unit mismatch, and a wrong-asset-type reading, and correctly accepts a valid one — the defect is purely in status-code mapping. Root cause: `telemetry_validating.go`'s `ErrUnknownMetric` is a bare `fmt.Errorf(...)`, defined outside `errors.go` and never added to `routes/errors.go`'s `digitaltwinStatusFor` switch (which enumerates every sentinel in `errors.go` but has no `ErrUnknownMetric` arm), so it falls through to the `default` case → 500, and `writeDigitaltwinErr` additionally masks the message to the generic `"internal error"` string on a 500, hiding the real reason (which metric/unit was rejected) from the caller. Every other validation failure in this package (`ErrInvalid`, `ErrInvalidConnection`, the four `*NotFound` sentinels) correctly maps to 400/404 with its real message — this is the one gap, confirmed by cross-checking every `Err*` sentinel in the package against the switch. Defect location: `routes/errors.go`'s `digitaltwinStatusFor` (missing arm) and/or `telemetry_validating.go:22`'s `ErrUnknownMetric` (not wrapped in `ErrInvalid`, unlike every other caller-input-validation sentinel in this package). Pinned by `routes/telemetry_validation_status_test.go`'s `TestValidatingTelemetry_UnknownMetricRejectionSurfacesAs500`, which asserts today's 500 and documents exactly what a fix flips it to. |
